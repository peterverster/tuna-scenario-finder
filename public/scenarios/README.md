# Published scenarios

This directory holds JSON files produced by the TUNA Scenario Selector. Each file is named `<uuid>.json` where the UUID is generated by the app on first export. Anything in this directory is **publicly readable** once committed and deployed — do not put sensitive client data here.

## How to publish a scenario

1. In the app, complete a scenario through Step 10.
2. Click **Share** in the header. The modal shows a public URL like `https://<host>/scenarios/<uuid>` and a **Download JSON** button.
3. Download the JSON. Save it to this directory exactly as `<uuid>.json` (matching the URL).
4. Commit and push:
   ```bash
   git add public/scenarios/<uuid>.json
   git commit -m "publish scenario <short-uuid>"
   git push
   ```
5. Vercel redeploys automatically. The Share modal's status badge will turn green ("Published — URL is live") on next open.

## Forking a scenario

If you want to publish a variant of an already-published scenario without overwriting it:

1. Open the original via the URL or via Import.
2. Make your changes.
3. Click **Share** → **Fork as new scenario**. A new UUID is minted.
4. Download the JSON for the new UUID and commit as above.

This way the original URL keeps serving the original content; the fork lives at its own URL.

## Privacy

Anything you commit here is in a public git repository and is publicly readable on the deployed site. If a scenario contains client-confidential factors, criteria, or context documents, **do not publish**. Use file Export (and ad-hoc sharing of the JSON over a private channel) instead.

## Schema

All files conform to schema version `tuna-scenario/v1`. See `_specification/scenario-portability-and-brand-refresh.md` §3.1 FR-001 for the full shape. The app validates schema, UUID format, matrix shapes, coupling symmetry, and the seed-space cap on every load.

## Navigation Tips

**New to the project?** Read in this order: `DOMAIN_MODEL.md` → `UBIQUITOUS_LANGUAGE.md` → `BOUNDED_CONTEXTS.md` → `ARCHITECTURE.md`. Allow ~30 minutes for the full pass.

**Implementing a new use case?** Start with `DOMAIN_MODEL.md` §"Application Layer" to confirm the use case is in scope, then `ARCHITECTURE.md` §"Inbound Port — `ProjectFacade`" for the contract.

**Reviewing a PR?** `UBIQUITOUS_LANGUAGE.md` is the fastest way to catch naming drift. `ARCHITECTURE.md` §"Dependency Rules" is the fastest way to catch a cross-layer import.

**Onboarding a strategist (non-engineer)?** `DOMAIN_MODEL.md` §"Executive Summary" + `UBIQUITOUS_LANGUAGE.md` cover everything they need without architecture noise.

## Keeping This Up-to-Date

These documents are generated by the `/ddd` slash command. To update:

1. Make your domain changes (rename a concept, add an entity, change an invariant).
2. Update `../_brief/tuna-scenario-tool-spec.md` if the spec needs to change.
3. Run `/ddd` again — it will regenerate this directory and archive the previous `DOMAIN_MODEL.md` to `archive/DOMAIN_MODEL_v<X.Y.Z>.md`.
4. Review the diff carefully. Domain documentation is high-leverage; a wrong term here will propagate into code, conversations, and PRs.

The model version follows semantic versioning at the domain level:

- **Patch (0.0.x)** — clarifications, glossary additions, nothing structural.
- **Minor (0.x.0)** — new entities, value objects, services, or use cases. Backwards-compatible.
- **Major (x.0.0)** — renamed core concepts, removed entities, restructured aggregates. Breaking.
